# 小宇宙单集

本 skill 借鉴 [xyz-dl](https://github.com/shiquda/xyz-dl) 的单集处理能力，只处理用户指定的一期。用户先问单集、随后说“下载这一期字幕”或“总结这一期”时，沿用已经核实的单集链接。

1. 按节目名、期数或用户给的链接定位单集。优先核对小宇宙单集页和制作方页面；确认节目名与期数同时匹配，避免把其他播客的同号单集当成目标。回复标题、嘉宾或主持（页面有写才填）、发布日期、时长、单集网页链接；缺失字段直说未找到。若同一期有多个候选，列出区别再请用户选择。
2. 用户要求“下载字幕/文字稿”时，先找该集公开且可实际获取的完整字幕或逐字稿。保存为 UTF-8 `.txt`；只有原文包含可靠时间码时才另存 `.srt`。文件名含播客名和期数，保存到用户指定目录；未指定时放到当前工作区之外的 `~/Downloads/播客字幕/`，回复绝对路径、来源链接和“官方字幕/第三方转录/自动转录”的类型。下载后检查文件非空且内容对应目标单集。节目简介、Show Notes、摘要和时间轴不能冒充完整字幕。
3. 如果公开来源没有完整文字稿，从该集公开音频生成本地自动转录；本机没有转录工具时，可按任务需要安装免费本地工具与模型，把音频和模型放在工作区外，明确标注自动转录及可能的识别错误。不要擅自调用收费转录服务。若无法取得文字稿或转录音频，说明具体卡点，不要声称下载成功。
4. 用户要求总结时，先取得并通读完整文字稿（官方字幕、可读取的第三方逐字稿或本地自动转录），注明来源类型，并尽可能给出对应时间点。节目简介、Show Notes、时间轴和第三方摘要不能替代逐字稿；若完整文字稿不可得，说明原因，询问用户是否接受基于简介的概要，不要自行降级。把总结保存为 UTF-8 Markdown 文件：用户当次指定目录时放在那里，否则放在当次工作目录；文件名包含播客名和期数，回复中给出绝对路径。若目标目录有 `AGENTS.md` 等本地规则，保存前遵守其目录、frontmatter 和链接约定。

总结时保留节目对数据本身的讨论，例如数据来源、训练语料、质量与污染、共享与保密、隐私和安全，说明其中的因果、权衡及具体案例。也保留与论点相关的数字、比例、时间跨度、样本或案例规模及比较结果，连同单位、口径、时间范围和对应时间点写清楚；区分节目引用的数据、嘉宾的估计与随口举例。自动转录中拿不准的数字先回听核对，无法核实就标明不确定，不要编造或把估计写成确定事实。

5. 完成逐字稿版总结时，若当前 GitHub 身份是 `merrier`，将本次使用的完整逐字稿同步到私有仓库 `merrier/podcast` 的 `逐字稿/<播客名>/`。文件名用核实后的单集标题及原有期数写法（例如 `E185`），按实际内容保存为 `.txt` 或带可靠时间码的 `.srt`；不要为了写成“第185期”而改动标题。上传前检查仓库仍为 private、目标文件是否已有用户修订；上传后核对远端文件，再把仓库文件链接写入总结并报告提交。若无法同步，保留本地逐字稿并明确报告，不能声称已上传。其他 GitHub 身份使用这个公开 skill 时，不写入 `merrier/podcast`，由使用者指定自己的仓库。

`xyz-dl` 当前 README 明确说明：免登录仅保证公开单集音频下载，字幕和部分元数据接口依赖登录态，且登录态下载可能触发账号风控。因此不要主动索取、保存、读取或使用小宇宙 token/device ID，不要调用登录接口、批量抓取或绕过付费/私有内容。只有用户明确要求使用其已配置的登录能力时，再核对项目当前说明和实际参数；仍需如实报告字幕接口是否成功。
