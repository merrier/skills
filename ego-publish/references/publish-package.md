# 发布清单、个人偏好与续做

开始发布或恢复任务时读取。设计借鉴 [video-publisher-skill](https://github.com/oil-oil/video-publisher-skill) 的内容包、素材身份和设置核验思路；实现使用 Python 标准库，不依赖其运行框架。**保留完整正文，统一方案获授权后连续提交其覆盖的平台。**

## 本机个人偏好

先运行 `python3 '<skill>/scripts/publish_package.py' config`。依次读取 `EGO_PUBLISH_CONFIG` 指定的文件，或 `${XDG_CONFIG_HOME:-~/.config}/ego-publish/config.json`；指定文件损坏时报告，不能忽略错误换一份配置。不存在则返回通用默认值，不自动写文件。

可配置字段：

| 字段 | 用途 |
|---|---|
| `schemaVersion` | 固定为 `1` |
| `timezone` | IANA 时区，如 `Asia/Shanghai`；最终定时保存带偏移的绝对时间 |
| `defaultPlatforms` | 未指定平台时的目标列表；默认仅小红书，不代表发布授权 |
| `keepResultTabs` | 完成后保留各平台独立结果页；默认 `true` |
| `bodyStyle` | 正文写作偏好；模型默认先用「emoji 字段：值」逐行列出已核实基础信息，缺项省略，再写实物观察、细节介绍和互动问题；格式与逐平台显示核验见主流程 |
| `platforms.<平台>.titleFormat` | 平台标题格式偏好 |
| `platforms.<平台>.collectionRule` | `per_post` 或 `model_scale` |
| `platforms.<平台>.collections` | 比例到合集全名的映射；必须到当前账号页面核实存在 |

平台键为 `xiaohongshu`、`bilibili`、`douyin`、`wechat-channels`。配置只保存用户明确的持续偏好；地点、某首音乐、某次时间及声明不从旧帖升级为默认。不要存 Cookie、账号凭证或“永久同意发布”。

优先级：**本次用户指令 → 本次已确认清单 → 本机偏好 → 通用默认**。将采用的偏好写入本次方案，之后不在上传途中重新读取并覆盖已确认值。账号、集合实际条目及音乐库结果仍须现场核验。个人配置、清单、素材和回执全部留在公开 skill 仓库之外。

## 一份清单，完整预览

素材目录中的 `发布清单.json` 是本次执行数据源，`发布方案.md` 是它的可读预览；平台稿从解析后的值生成，不各维护一份可能失配的正文。创建清单时生成一次 UUID `taskId`；续做沿用，新选题／明确重发用新 UUID，并保留旧帖子关联记录。

图文示例（路径和文字须替换为本次实际值）：

```json
{
  "schemaVersion": 1,
  "taskId": "2af24dd6-beba-4bb9-bbc1-04cd14bd9aba",
  "kind": "image",
  "platformOrder": ["xiaohongshu", "bilibili"],
  "shared": {
    "title": "小车身，大尾翼",
    "body": "📏 比例：1:43\n🧱 材质：已核实的材质\n🏷️ 品牌：已核实的模型厂牌\n🚗 车型：已核实的车型\n🎨 涂装：已核实的版本\n\n实物观察与细节介绍。\n\n给读者的互动问题。",
    "topics": ["汽车模型"],
    "media": ["/素材目录/封面_3x4.png", "/素材目录/前侧.jpg", "/素材目录/后侧.jpg"],
    "covers": {},
    "schedule": {"mode": "scheduled", "at": "2026-09-11T20:18:00+08:00"},
    "location": null,
    "music": null,
    "visibility": "public",
    "action": "submit"
  },
  "platforms": {
    "xiaohongshu": {"account": "本次目标账号", "settings": {"collection": null, "declaration": "本次已确认值"}},
    "bilibili": {
      "account": "本次目标账号",
      "settings": {"collection": null, "declaration": "本次已确认值"},
      "overrides": {
        "title": {"from": "小车身，大尾翼", "value": "小车身，大尾翼 | 1:43 Ford Escort"},
        "media": {
          "from": ["/素材目录/封面_3x4.png", "/素材目录/前侧.jpg", "/素材目录/后侧.jpg"],
          "value": ["/素材目录/前侧.jpg", "/素材目录/后侧.jpg"]
        },
        "covers": {"from": {}, "value": {"main": "/素材目录/封面_16x9.png"}}
      }
    }
  }
}
```

- `shared` 表中字段均显式填写；不配乐／不添加地点用 `null`，不是“待核验”。入口不支持某字段时在对应平台差异和 `settings` 写明，由用户确认实际处理方式；不能拿 `null` 隐藏必要选择。
- `body` 保存实际展示的完整文字；示例中的说明文字须替换为已核实值，缺项整行删去。基础信息每项用一个 `\n` 分行，与后续介绍用 `\n\n` 分段；平台恢复后核验实际换行。不能为了工具方便退化成标题加标签；话题单独关联平台原生节点。
- 需要配乐时，`music` 对象写明 `title`、`artist` 及已确认的 `version`／`segment`，不以同名歌曲代替同一版本；视频原声保留方式写入平台 `settings` 并列入预览。
- `overrides` 只写平台差异，支持覆盖任一共享字段。`from` 保存制定该版本时的共享值，`value` 是用户要看到的实际平台值。共用字段更新导致 `from` 失配时，脚本拒绝旧覆盖；重新判断保留／改写／删除该覆盖，更新预览并确认受影响项。不能只机械更新 `from` 掩盖未审阅文案。
- `kind: video` 时每个平台 `media` 只放一个已确认成片，封面放在 `covers`。封面键按当前实际入口的槽位命名（如 `main`、`portrait`、`landscape`），各槽位填写明确文件；不从图文经验推断视频要求。读取同名字幕可辅助文案，但仍核对画面与事实。
- `schedule` 立即发布为 `{"mode":"immediate"}`，定时必须为带时区偏移的完整 ISO 日期。`action` 为 `draft` 或 `submit`。两者只是计划值；脚本和 JSON 均不授予发布权限，实际用户对完整方案的授权才有效。

先运行 `snapshot` 保存待审阅版本，用该文件的 `platforms.<平台>.effective` 生成用户看到的完整预览。用户确认内容后，在 `发布方案.md` 将真实确认语句、时间及草稿／提交范围关联到这份快照，不重算指纹替换用户看过的版本：

```bash
python3 '<skill>/scripts/publish_package.py' snapshot '/素材目录/发布清单.json' --output '/素材目录/发布清单.版本1.json'
```

快照包含路径、大小、SHA-256、图片顺序、独立封面和各平台完整值，不覆盖已存在快照。文案或素材调整后保存新序号快照，展示变化并关联其实际确认；保留既有提交记录与对应指纹。路径可显式指向已确认的软链接素材，但快照记录真实目标；盘点脚本仍默认跳过软链接。快照存在不等于用户已确认，也不证明媒体可解码或已通过平台校验。等待确认期间文件若改变，下一次 `check` 应报告变化，不能将新文件自动视为已经认可。

## 续做与防重复

再次操作前及每个平台提交前重新计算文件指纹，与本篇最新已确认快照比较：

```bash
python3 '<skill>/scripts/publish_package.py' check '/素材目录/发布清单.json' --against '/素材目录/发布清单.版本1.json' --receipts '/素材目录/发布进度.json'
```

首次没有进度文件可省略 `--receipts`。`发布进度.json` 保持简单：

```json
{
  "schemaVersion": 1,
  "taskId": "2af24dd6-beba-4bb9-bbc1-04cd14bd9aba",
  "platforms": {
    "xiaohongshu": {
      "status": "submitted",
      "fingerprint": "该次提交对应的脚本输出指纹",
      "recordFile": "小红书发布记录.json",
      "pageLabel": "本次实际保留页标签"
    }
  }
}
```

点击发布前先写入 `submit_started`；回到管理页验证后记 `submitted`，保留真实状态（预约／审核中／已公开）在平台记录中。响应不明写 `unknown`，不得改记普通 `failed` 以触发重试。`draft` 表示已验证平台草稿，`failed` 仅用于未提交的步骤失败或管理页已确认未提交；不删除历史证据。

| `comparison.platforms.<平台>.next` | 应执行的动作 |
|---|---|
| `needs_confirmation` | 新平台或内容／图片／封面已变，列出 `changed` 中受影响部分；结合当前对话补齐其确认，不重问未变平台 |
| `resume_and_verify` | 清单未变；重新读取实际页面，仅补缺项；已有提交授权有效，符合核验后直接执行计划动作 |
| `needs_new_time` | 未提交平台的确认时间已过，只确认新时间，不自动挪到下一天 |
| `verify_result_only` | 曾提交、开始提交或状态不明；先查管理页，禁止自动重新上传投稿，即使素材已改 |

`removedPlatforms` 仅报告范围变化，不撤回或删除任何作品。明确重发另起任务，清单内保留与旧记录的关系，先确认新增发布范围。

旧帖子若只有 Markdown 和历史发布记录，先读其中素材、时间、账号与结果，再建立清单。不能把今天重新算出的指纹冒充旧投稿当时的指纹，也不能因为没新格式快照就重发。已提交／不明项先记进度并核验管理页；历史字段无法确认则如实保留未知。

## 设置与媒体的实际核验

每个字段按 **读取当前值 → 已正确则跳过，否则设置 → 独立读回验证** 执行。读取、操作、验证是三个阶段，不能用“点击返回成功”充当已选结果。对合集、声明、音乐、定时统一采用这条规则；下拉内高亮项不等于发布页已接受，关闭弹窗后核对主表单，草稿恢复后重新读取。一次修改未生效先检查焦点、可见范围和页面新状态；不重复盲点。仅修复差异，避免已正确字段被开关切回。

视频上传必须区分：`empty` → `uploading` → `processing` → `ready`，另有 `failed`／`unknown`。已在上传目标成片就等待观察，不再次注入同一文件；存在他人／其他选题草稿先停在该平台并核对。`ready` 需有当前目标素材对应的页面完成状态、时长／方向核对、可播放预览及无阻断错误；进度 100%、文件输入成功或本地预览卡均不足够。若入口缺少某个信号，使用等效的实际证据并说明，不能填成已验证。

封面按槽位核验：选入本次文件 → 完成裁切确认 → 弹窗关闭 → **主编辑页对应槽位显示已接受封面** → 检查标题与模型完整。视频有多个槽位时逐个核对，不能因为第一个成功就全标成功；图文首图还须检查相册第一张与顺序。恢复草稿后重新读取，裁切弹窗、头像、手机预览缩略图或 `data:` URL 都不能替代主编辑页证据。

在 `<平台>发布记录.json` 的 `preflight` 增加必要证据：

- `fields`：各字段的 `expected`、`actual`、`verifiedAt` 与 `source`（主表单／草稿恢复页）；正文带 emoji 时附实际字符读回与显示截图，说明已验证阶段；核验过才标一致。
- `upload`：当前阶段、源文件指纹、已上传数量及顺序，视频实际时长与播放验证；未知项明确为未知。
- `covers`：每槽位源路径与 SHA-256、主表单是否接受、裁切效果、读取时间与截图／可见文字证据。
- `browser`：当前工作区、平台页标签与实际结果／管理地址；独立核验的帖子 ID、预约时间和状态。

只存必要的可见证据，不存 Cookie、令牌、签名上传 URL、整份网络日志。这里规定的是执行与验收方法；Python 测试只验证清单及续做逻辑，不代表视频投稿已实测。
