# 小红书：Ego 发布适配

只在目标平台为小红书时读取。网页结构与限制会变化，以下是 2026-09-08 在创作服务平台的实测线索，执行时仍以当前页面为准。

## 验证范围与入口

- 已验证：图文上传、富文本与原生话题、浏览器本地草稿及恢复、合集创建与选择、地点搜索、原创／内容类型声明、立即与定时提交、管理页结果、删除指定旧私密笔记。
- 视频：复用公共确认及核验流程，通过实际“上传视频”入口执行；本次没有视频成片的端到端发布验证，不能称为已实测。
- [发布页](https://creator.xiaohongshu.com/publish/publish)、[笔记管理](https://creator.xiaohongshu.com/new/note-manager)。先确认页面右上角账号。
- 实测图文页面显示最多 18 张，PNG/JPG/JPEG/WebP、单图最大 32 MB；标题候选按 20 字以内准备。都作为历史参考，最终读取当前计数器、格式说明和校验结果，不把图片规则套给视频。

## 上传素材

### 图文

1. 从发布页选择“上传图文”，确认已进入图片输入。只上传已选定的文件：一张首图封面在前，随后原片；不要传入整个目录、五套封面或发布截图。
2. 优先用可用的上传 helper；若 `uploadFile` 报不支持，可用标准 CDP 文件输入。先观察当前 `input[type="file"]`，确保找对接收图片的控件；不要假定页面只有一个文件输入。

```javascript
// 放入 ego-browser nodejs heredoc；uploadSelector 和 files 来自本轮已核验结果。
const { root } = await cdp('DOM.getDocument', {});
const { nodeId } = await cdp('DOM.querySelector', {
  nodeId: root.nodeId, selector: uploadSelector
});
if (!nodeId) throw new Error('未找到当前上传控件');
await cdp('DOM.setFileInputFiles', { nodeId, files });
cliLog(await snapshotText());
```

3. 等待全部图片上传完成，核对图片总数、顺序与预览。实测 `.format-img img` 是上传缩略图，可检查 `complete`、`naturalWidth`；选择器变化时重新定位。缩略图方形裁切不等于成品被裁切，检查手机预览是否保留整车。

### 视频

1. 选择“上传视频”，读取当前文件、时长、尺寸、编码和大小要求；只上传已确认成片，不把多个片段自动串成一条。
2. 等待上传、转码／处理和校验完成。确认实际时长、方向、封面及可播放预览；不能从上传进度达到 100% 推断视频已可发布。
3. 按页面现有能力选择视频封面／截帧，若提供多种封面视图分别检查。现有图片可以作为封面候选，但不因此把视频切换成图文；无合适封面时先给用户看方案。
4. 填写标题、正文／简介和话题，按实际出现的控件设置合集、地点、声明、可见范围和定时。图文入口已知的选择器、草稿位置和字段可选性不能直接当作视频事实。
5. 保存并恢复草稿，复核成片和设置；收到对应视频的完整发布确认后提交，再到管理页核验。格式不兼容或必填项缺失时明确卡点，不发布空白／占位视频作为测试。

## 标题、正文与话题

- 标题曾使用 `input[placeholder="填写标题会有更多赞哦"]`。当前输入框与计数器是最终依据；不要静默截断用户确认的文案。
- 图文正文曾是 `div.tiptap.ProseMirror`。按 `ego-browser` 要求先用很小的可撤销写入验证编辑面，再用真实键盘事件填充；不能把字输到隐藏输入或别的字段。
- 实测 `Input.insertText` 可插入多段正文，但后续输入前应显式移动到文末，否则话题可能插进前一段。替换既有正文前先保留完整内容，只有用户确实要求替换时才全选。

```javascript
await click(editorSelector); // 当前已验证的正文编辑器
await cdp('Input.dispatchKeyEvent', {
  type: 'keyDown', key: 'End', code: 'End', commands: ['moveToEndOfDocument']
});
await cdp('Input.dispatchKeyEvent', { type: 'keyUp', key: 'End', code: 'End' });
await cdp('Input.insertText', { text: ' #' + topic });
```

输入 `#话题` 后等待候选出现，再选**名称完全匹配**的结果。不要把瞬间“无结果”当成最终查询结果，也不凭输入的井号文本认定关联成功。曾可从可见 tooltip 的 `#creator-editor-topic-container .name` 查找选项；已关联节点曾为正文内 `a.tiptap-topic`，`data-topic` 带名称和标识。查询限定正文，排除右侧预览重复的节点。缺少目标话题时说明并保留有用正文，不擅自换成无关热门词。

核验正文段落与编辑器预览。`innerText` 可能在空段间返回额外换行；以段落和实际截图判断，不为此反复覆盖正常正文。

## 合集、地点与声明

### 合集

“加入合集 → 选择合集”显示已有合集与“创建合集”。选择器曾为 `.collection-plugin-button`。根据内容类型／比例匹配合集；1:43 图集不要因为是车模就自动归到 1:64 视频评测。

用户指定新合集名称后，先确认列表没有同名项，再打开创建表单。实测有名称（20 字）、简介（50 字）与“创建并加入”；简介非必填则可留空，不追加未要求的定位文案。点击后等待完成；表单暂时还在或按钮 loading 时不要重复创建。核对编辑页和预览均显示目标合集。

### 地点

点击“添加地点”，在该下拉控件的文本输入搜索，等待候选。选择名称及地址符合用户意图的真实条目，不能仅把搜索词留在输入框。存在明显主地点时优先主地点；确有同名异地且不能判断才请用户选择。

示例：用户指定首钢园，实测主条目为“首钢园／北京市石景山区石景山路68号”，不要误选停车场、酒店或南北门。该地点不是默认设置。保存后重新打开核对已选值。

### 声明

原创开关可能弹出《原创声明须知》，读取当前说明后按用户已确认的原创情况选择，勾选须知并点“声明原创”；该按钮与最终“发布”不同。声明项不能推断为审核已通过。

“添加内容类型声明”与原创独立，曾提供 AI 合成、虚构演绎、营销等选项。遵循本篇用户选择及实际来源；不把历史勾选直接迁移到所有新帖子。取消已选声明时用页面现有清除／取消能力并验证，不把重复点击当作一定能取消，也不绕过强制校验。

## 定时与草稿

“更多设置”中的可见范围与定时分别核对。打开定时开关后填写**本次确认的绝对日期与时间**，最终按钮才变成“定时发布”。

- 日期控件曾支持日历及小时／分钟列表。直接填写文本后可能没有提交到组件状态，应检查实际值、开关以及重新打开后的结果。
- 先选日期，再选小时、分钟；每步后观察，时间选项可能在滚动区外，或选中后菜单关闭。重新打开后再选下一项。不要点击被裁掉的元素中心，避免落到背后的开关。
- 需要时截图定位、滚动对应列表；也可对已确认的标准 DOM 选项使用 `element.click()`。不改框架内部状态、不跳过禁用范围。
- 保存／恢复后再核对定时开关、具体年月日和分钟。不能把浏览器显示的日期文本当成预约已经提交。

实测“暂存离开”提示保存成功，并打开“草稿箱”；草稿保存在**当前浏览器本地**，不是账号云端。打开草稿里的“编辑”，复核素材、文案、话题、合集、地点、声明、可见范围和定时。若视频入口另有机制，按当前页面核实。

本地草稿需要用户继续修改／确认时保留该 Ego 工作区，不能关掉后只给一个通用发布页链接声称用户能恢复。记录工作区并移交；恢复操作收到明确确认后用 `claimTaskSpace`，避免对已经结束的工作区盲用 `takeOverTaskSpace`。

## 提交与结果

完整预览已确认且用户明确要求立即／定时提交后，重新读取当前按钮，**只点击一次**。定时提交也可能先显示“发布成功”，这不表示已即时公开。

进入管理页，找匹配的笔记并读取日期及状态。图文实测 `.note-card` 包含 `.note-card__title`、发布时间、私密或定时标记；标题相同可能有两篇。定时稿应出现“定时发布”和准确时间；显示“审核中”就如实记录，不声称已通过。没有结果或发生超时，先查管理页，不能直接再发一篇。

已发布笔记的编辑页在本次实测中没有定时选项。用户要求改为定时，可以先保留旧笔记，准备新草稿并说明新增关系；最终提交和删除旧笔记各自按用户指令执行，不以“去重”为由自行删帖。

### 用户要求删除旧笔记时

1. 在同名卡片中以 ID（如可见）、发布时间和“仅自己可见”识别旧版本，同时确认应保留的定时卡片及时间。
2. 当前卡片的删除动作曾使用 `.note-card__action-btn--del`；先核对作用范围及 tooltip，不对全页第一个删除按钮操作。
3. 确认框标题可能截短，目标身份以此前卡片为准。用户已明确授权删除该篇时，正常点击确认，等“删除成功”。
4. 刷新管理页，确认旧版本消失、定时版本仍在。更新记录，不把旧截图当成当前状态。

## 容易出错的 UI 细节

- `snapshotText()` 中的“button”不保证 DOM 标签一定是 `<button>`，所以 `document.querySelectorAll('button')` 返回空不能证明没有发布按钮。用当前语义 ref 或实际 DOM 定位。
- `normalize-space(text())` 对嵌套文字或多个文本节点可能失配；先看元素结构，必要时用精确控件范围及 `normalize-space(.)`，不要改成匹配整页的宽泛祖先。
- 跳转、弹窗、上传和建议结果是异步的。一次操作后观察新状态，等待加载完成；不能因为旧控件尚在语义树中就再次触发外部写入。
- 下拉或关闭的弹窗可能仍在 DOM；优先可见选项和有效 ref。选项滚动、输入焦点和定位使用同一轮实际页面数据。
- 页签 ID 可能变化，旧 ID 失效时从当前工作区重新列出页签。出现控制权错误则立即按依赖 skill 停止，不能用重新建工作区绕过。
