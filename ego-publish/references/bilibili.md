# 哔哩哔哩：Ego 发布适配

目标为哔哩哔哩、B站或 bilibili 时读取。以下来自 2026-09-08 的实际操作；入口、限制与选择器是定位线索，每次仍读取当前页面。遵循主 skill 的素材选择和发布授权边界。

## 范围、入口与账号

- 已验证：专栏图文编辑、六张原片与独立横版封面、平台草稿保存及重新打开、原生主话题、原创声明、定时提交、管理页「审核通过，定时待发布」。
- 文集入口和已选文集的保存／恢复已验证；接回用户审阅的页面时文集已选好，创建过程未实测。独立动态、视频成片投稿、立即公开及删帖未在本次流程中实测，不把专栏行为套给这些入口。
- [创作中心](https://member.bilibili.com/) → 投稿 → 专栏投稿 → 新的创作；实测[专栏草稿箱](https://member.bilibili.com/platform/upload/text/new-article)。照片按长图文专栏准备，与用户指定的动态或视频投稿区分；只有照片时不自动合成为视频。
- [个人空间](https://space.bilibili.com/)会跳到当前登录账号的 UID。核对昵称及「视角：我自己」；访问一个旧 UID 的空间不代表登录了该账号。账号与用户预期不同先确认或移交切换。
- 切换账号后重新检查现有编辑器。旧页面可能仍显示旧账号；有未保存内容先保留，空编辑器可刷新，再核对账号。不要在旧账号下保存／提交来测试登录。

## 标题与素材组织

用户偏好格式：**引人入胜的文案 | 模型信息介绍**。前半段写真实的造型、配色或收藏看点，后半段优先列厂牌、比例、车型，再按空间加入年款、版本或涂装。不堆砌未经核实的价格、限量和评价。

示例：`没有大尾翼也抢眼 | Eagle’s Race 1:43 Viper RT/10 1998银色`（47 个字符）。

- 实测专栏标题提示「建议30字以内」，输入框 `maxlength=50`；以当前计数器和校验为准。这里的 50 是专栏编辑框限制，不是 B 站所有投稿类型的统一限制，也不是小红书的 20 字限制。
- 新标题给 2–3 个不同角度的候选，按主 skill 确认具体文字；确认后不静默截断。已确定定时时间，用户随后说「就用 A，发布吧」，应沿用该定时安排提交，不改成立即发布，也不重复索要同一确认。
- 正文图片保留原画幅，按整车、不同角度、细节排列。张数按本次内容决定，不固定六张。独立封面与正文分开，现有 16:9 封面可作为候选，不把全部比例封面都插入正文。
- 实测图片入口支持 `.jpg/.png/.webp/.gif/.heif`，静态图片不超过 20 MB、GIF 不超过 8 MB；独立封面提示 JPG/PNG，建议不低于 600×336，非 GIF。都要以当前入口要求复核。

## 编辑器与上传

实测编辑器在同源 iframe（地址含 `/york/read-editor`）里，正文是 `.tiptap.ProseMirror`，工具栏还包含 Shadow DOM。先用 `snapshotText()` 定位：

- 普通 CSS helper 可能只搜索顶层页面；iframe 内字段可用当前 ref。若点击位置偏移，用截图或当前 iframe 矩形加内部控件矩形计算顶层坐标；不要反复点旧 ref。普通按钮／选项也可在已确认的同源 `contentDocument` 中调用原生 `element.click()`，不改框架内部状态。
- 富文本先做少量可撤销输入并验证位置。上传前明确把光标移到目标段落之后，再检查图片没有切断句子。正文已有图片时，避免为了调整空行全选重写；局部替换也可能影响相邻图片，改后检查完整段落、图片数量与顺序，出错先撤销恢复。
- `innerText` 的额外换行、编辑器的「点此添加图片注释」占位提示不等于实际正文文字；按段落和预览核对，不把占位提示复制到发布文案。
- 上传正文图片的入口曾为 `eva3-toolbar-image` 内的「上传图片」；不默认选择「上传图片并添加水印」。文件输入可能临时创建且不挂在可查询 DOM 中。

普通上传 helper 找不到该输入时，可从**当前实际文件选择动作**捕获标准 CDP 事件。在同一个 heredoc 内完成监听、点击和传入已核验的绝对路径：

```javascript
// uploadPoint 是当前上传菜单项的顶层页面坐标；files 是已选文件的绝对路径数组。
await cdp('Page.enable', {});
await cdp('Page.setInterceptFileChooserDialog', { enabled: true });
await drainEvents();
try {
  await click(uploadPoint);
  await wait(0.5);
  const events = (await drainEvents()).filter(e => e.method === 'Page.fileChooserOpened');
  if (events.length !== 1 || !events[0].params.backendNodeId)
    throw new Error('未能唯一定位本次文件输入，先重新观察页面');
  await cdp('DOM.setFileInputFiles', {
    backendNodeId: events[0].params.backendNodeId, files
  });
} finally {
  await cdp('Page.setInterceptFileChooserDialog', { enabled: false });
}
```

不能复用历史 `backendNodeId`。需要 `Page.enable` 才能可靠收到这次实测中的文件选择事件；没有事件先判断是否只打开了下一层菜单，不盲目重传。传入后检查全部图片与错误提示；编辑器里显示 `data:` 图片只证明本地预览存在，保存后重新打开仍能加载才是平台保留的证据。

独立封面流程：发布设置 → 自定义封面 → 添加封面 → 本地上传 → 截取位置 → 确定。最后一个「确定」只确认封面；检查效果展示中的标题、轮圈和车身未被裁掉。本次已有 16:9 封面适配成功，没有修改原文件。

## 话题、文集和声明

- 「添加话题」打开搜索及单选列表，选择相关的原生主话题后点「确认」。本次使用「汽车模型展示」，不把它固定成所有玩具帖的话题。不要照搬小红书的多个话题字段；页面另有正文标签提示时，需核验实际关联结果，不能把井号纯文本当成已关联主话题。
- **话题在本次草稿重新打开后未保留。** 恢复、切换页面或刷新后复查；最终提交前重新选择并核验名称，接着在当前页面提交。不能仅凭曾点击「确认」认定最终稿包含话题。
- B 站这里叫「文集」。先读已选项及已有列表，用户已选好的保留，不创建同名重复项。需要新建时遵循用户确认的名称，并实测当前创建表单；未走通不得称为已创建。实测空列表下「取消」与「确定」都可能禁用，可用该对话框的关闭按钮退出。
- 定时、文集、可见范围、评论、精选评论、原创和 AI 辅助创作声明分别核对。原创不能替代 AI 声明；按本篇用户选择、真实来源和当前平台要求设置。
- 本次专栏编辑页没有发现地点字段，不把小红书的地点写成已在 B 站设置，也不据此断言其他 B 站入口都不支持地点。

## 定时与草稿恢复

实测定时范围为当前时间加 2 小时至 7 天内，以**北京时间 UTC+8**为准。将用户的「明天」换算成绝对日期；这个范围和已选择的某次 18:18 都不是所有帖子的固定设置。

1. 开启定时，先选日期，再选小时和分钟，点击时间弹层内的「确定」。观察当前月份、禁用日期及日期／时间最终显示，不跳过控件限制。
2. 时间弹层曾有两列 `.time-column`，分别为小时和分钟；选项需要滚动时只滚动目标列表。选择后核验最终值，例如 `2026-09-09` 与 `18:18`。
3. 点击「保存为草稿」，等实际保存成功。本次自动保存曾失败，手动保存后恢复成功；不要把失败提示或本地 Markdown 当成平台草稿已保存。
4. 从平台草稿箱重新打开该篇，核对标题、正文、图片、封面、文集、声明、定时开关和具体时间。恢复后的编辑 URL 含 `aid`；记录实际 URL 与草稿标识，不拼造公开帖子链接。本次平台草稿可通过草稿箱恢复，与小红书浏览器本地草稿机制不同。
5. 新编辑页验证成功后，关闭同篇的旧编辑页，避免多个页面自动保存覆盖新设置。恢复丢失的话题按上一节处理。

## 提交与结果核验

定时开关开启后，最终按钮在本次仍叫**「发布」**。收到本篇完整预览及明确发布授权后，核对已确认标题、账号、全部发布设置与本次素材，再点击一次；不能从按钮文字推断是立即发布。

- 本次成功提示为「你的专栏已提交成功」；点「点击查看」进入[图文管理](https://member.bilibili.com/platform/upload-manager/opus)。
- 找最终标题及对应封面的卡片，核对定时日期、分钟与状态。本次为「审核通过，定时待发布」；这是审核通过的预约稿，尚未公开。若显示审核中、失败或其他状态，原样记录，不能套用本次成功结果。
- 不确定是否提交成功时，先查管理页；不重复点击发布或另建同内容稿件。管理页没有公开链接时交付管理地址和核验截图，不把草稿 `aid` 当作公开专栏／动态 ID。
- 素材目录沿用 `哔哩哔哩发布稿.md`、`哔哩哔哩定时发布记录.json` 与必要的管理页截图。记录最终文案、账号、素材、话题、文集、声明、可见范围、绝对时间和实际状态；历史草稿截图注明旧版本。

以上定时提交流程于 2026-09-08 实测并核验，本地素材与发布记录不随公开 skill 分发。历史结果不授予以后发布其他素材的权限，也不证明已到点公开或所有 B 站内容类型均已验证。
