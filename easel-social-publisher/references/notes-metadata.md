# Notes 元数据回写规则

当发布源是用户的 Markdown 笔记或 Obsidian vault，发布完成后把最终分类和话题写回源笔记。回写只记录真实完成的结果，不把预览、候选或失败计划写进正式属性。

## 1. 读取仓库规则

修改前读取源仓库适用的 `AGENTS.md`、目录约定、frontmatter 风格和验证命令。私密目录没有当次授权时必须在扫描前排除；不得为了找源稿读取私密笔记。

工作区可能已有用户改动。只修改本次发布的源笔记，保留其他文件和原有属性，不顺手格式化正文、索引或相邻笔记。

## 2. `category` 记录合集

- 用户确认的合集或文集名称写入 YAML 的 `category`。
- 多个平台使用同一名称时写一个标量，例如 `category: 生活杂谈`。
- 不同平台使用不同合集名称时先让用户选择一个 canonical category；不要自动写成某个平台专用名称，也不要自行改成列表或映射。
- 本次未使用合集时不新增 `category`，也不清除已有值。
- 合集创建失败、审核未通过或内容未真正加入时，不把候选名称写成已完成；保留旧值并报告差异。

## 3. `tags` 记录最终话题

- 把用户最终确认并实际用于内容的主题标签写入 YAML `tags`。
- 去掉 `#`，保持有意义的大小写与专有名词，例如 `BLG`、`LPL`。
- 去重并保留原有无关标签；不因为某个平台没有精确话题实体就删除文章主题标签。
- 平台自动推荐但用户没有选择的话题不写入。
- 使用 YAML 列表，匹配仓库现有格式。

## 4. `published_at`、`urlname` 与 `platforms`

- `published_at` 记录文章首次在至少一个平台正式公开的日期，格式为 `YYYY-MM-DD`。已有值时保留最早日期，后续分发不覆盖。
- `urlname` 根据最终标题生成简短英文 URL path。使用小写 ASCII 字母、数字和连字符，不带开头或结尾 `/`、文件扩展名、空格、下划线和连续连字符，例如 `blg-champion-2026`。
- `urlname` 优先翻译标题的核心对象和事件，不逐字拼音化；通常使用 2–5 个片段。年份、版本或地区只在有助于区分内容时保留。
- 写入前在获准扫描的非私密笔记中检查 `urlname` 唯一性。冲突时优先增加题材、年份或版本等真实区分信息；仍有多种合理方案时请用户选择，不追加无意义随机数。
- 已有 `urlname` 时默认保留，避免公开链接变化；但纯 14 位数字的 `urlname` 视为博客模板生成的时间戳占位符，在首次正式发布时替换为标题生成的英文路径。标题修改不自动重命名已经正式使用的英文路径，除非用户明确要求迁移 URL。
- `platforms` 使用 YAML 列表，记录内容管理页已回读为正式提交且最终公开的平台标识，例如 `bilibili`、`xiaohongshu`、`douyin`。
- 只保存草稿、预览、上传失败、跳过、未核实或仍未提交的平台不写入。
- 平台后续新增时去重追加，不改变已有顺序；平台内容被删除或下线时不要静默移除，先向用户确认是否同步历史记录。
- 使用稳定的小写平台标识，不写账号名、后台 URL、作品 ID 或审核状态。

## 5. 同步已确认修正

发布前用户已经确认的人名、年份、标题或事实修正，应同步到源笔记和所有衍生稿，避免 notes 继续保留已知错误。只同步明确确认的修改，不把平台摘要或缩写反写成长文。

## 6. 其他顶部字段

默认维护 `category`、`tags`、`published_at`、`urlname` 和 `platforms`。其他属性得到确认后再写：

- `status`：仓库已有明确状态枚举时记录草稿、已发布或归档；没有约定时不自创枚举。
- `cover`：仓库已有封面属性约定时记录相对资源路径；没有约定时继续使用正文图片引用。
- `source_url` 或 `canonical_url`：存在稳定公开链接且用户希望回链时记录；内容管理后台 URL 不算公开链接。

不把账号 ID、Cookie、Token、验证码、后台管理 URL、浏览器路径、临时预览目录和本机绝对路径写入 frontmatter。

## 7. 验证

至少检查：

- YAML 可以解析，`category`、`tags` 和 `platforms` 没有重复或空值，`published_at` 是合法日期，`urlname` 满足 `^[a-z0-9]+(?:-[a-z0-9]+)*$` 且在获准范围内唯一。
- 源笔记仍有正确标题、正文和附件引用。
- 新增或修改的附件相对路径可用。
- 执行源仓库要求的索引检查和 `git diff --check`。
- `git status --short` 中没有由本次操作产生的私密目录变更。

除非用户明确要求，不提交、不推送 notes 仓库；Skill 仓库的维护授权不自动扩展到内容仓库。
