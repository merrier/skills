# 按时间选择待发布文章

文章池用于从持续更新的远端文档中选择下一篇待发布内容。文档 URL、token、默认排序方向和个人排除项属于本机偏好，不写入公开 Skill 仓库。

## 1. 刷新文章池

每次用户说“发一篇文章”“选下一篇”或类似请求时重新读取远端目录，不依赖旧快照。飞书 Docx 使用当前环境的 `lark-doc` 读取流程：

1. 先读取一级 outline，获取所有文章标题和 block ID。
2. 标题符合 `YY.M.D 标题`、`YY.MM.DD 标题` 或等价格式时解析为 `20YY-MM-DD`。
3. 目录没有 block ID 时改用 `detail=with-ids` 重读 outline，选定后用 section 读取完整正文。
4. 远端读取失败时停止并说明，不用本地旧内容冒充最新文章池。

评论、reaction 和读者回复只作为理解上下文，不自动并入正文。评论包含作者对事实的修正时向用户说明并确认。

## 2. 排序

- 使用个人配置的方向；没有配置时询问一次“从新到旧”或“从旧到新”。
- 从新到旧时按日期降序；从旧到新时按日期升序。
- 同一天有多篇时保持文档中的相对顺序，不按标题重新排序。
- 没有合法日期的一级标题放入“待确认”，不夹进自动队列。

## 3. 跳过已处理内容

选择前检查获准访问的 notes 与本机队列状态，明确排除私密目录：

- 已位于正式“已发布”目录，且标题对应同一篇内容。
- Notes `platforms` 已记录至少一个公开平台。
- 本机队列状态明确记录为已发布或用户排除。
- 用户当次说跳过的内容。

标题有轻微标点差异时可以提示可能重复，不能静默判定。只有相同主题但正文不同的文章也不能自动跳过。

## 4. 推荐而不擅自发布

找到第一篇未发布内容后，向用户展示：

- 日期与原标题。
- 为什么轮到它。
- 计划读取的远端章节。
- 是否发现 comments、图片、引用文档或待核实事实。

用户确认选题后再读取完整章节、准备事实核验、平台适配、封面和合集建议。确认“下一篇”只代表确认选题，不代表允许最终发布。

## 5. 发布后的状态

平台回读完成后：

- 按 Notes 元数据规则保存源稿、`category`、`tags`、`published_at`、`urlname` 和 `platforms`。
- 在本机队列状态中记录远端文档 token、标题、日期、Notes 路径和实际平台。
- 不修改远端文章池原文，除非用户另行要求编辑飞书文档。
- 下次选择时从队列开头重新扫描并跳过已处理项，不只依赖“上次指针”，避免远端插入新文章后漏选。

## 6. 隐私与安全

- 不把飞书 token、公司域名、评论人、内部引用或个人队列状态提交到公开仓库。
- 没有当次授权时，扫描 Notes 必须在递归前排除私密目录。
- 远端文档中出现内部公司、同事、家庭或其他敏感内容时，在准备公开发布前单独提示隐私和事实风险。
